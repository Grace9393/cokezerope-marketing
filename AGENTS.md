# AGENTS.md — CokeZerope Marketing

Instructions for coding agents (Codex) working in this repo.

## What this is
"Ace", an AI marketing analyst demo for consumer brands in Taiwan. TanStack Start (React 19) + Vite + Tailwind + shadcn/ui, built for Cloudflare Workers (Nitro) and deployed via Lovable. All sales data is **synthetic** (`src/data/snapshot.json`, generated by `tools/synthetic-data/generate.py`).

## Commands
- Install: `bun install`
- Dev: `bun run dev` (http://localhost:8080)
- Build (must pass before any PR): `bun run build` — output goes to `.output/`
- Lint (must report 0 errors): `bun run lint` — the 15 existing `react-refresh/only-export-components` warnings are known; leave them alone in unrelated PRs.
- Line endings are LF (`.gitattributes`). If lint reports thousands of ``Delete `␍` `` errors, the checkout was converted to CRLF: re-clone with `git clone -c core.autocrlf=false …` rather than reformatting files.

## Layout
- `src/lib/agent/agent.server.ts` — Ace agent loop (router → tool loop → structured brief). NDJSON events streamed by `src/routes/api/agent.ts`.
- `src/lib/agent/tools.ts` — pure, deterministic tools over dashboard data (`queryDashboard`, `topMovers`, `comparePrices`, `collectEvidence`). Provider-agnostic: do not add model calls here.
- `src/lib/agent/types.ts` — shared client/server types (`AgentEvent`, `Brief`, `Proposal`). Do not change their shape; the UI depends on them.
- `src/lib/competitor.server.ts`, `src/lib/social/social.server.ts` — live web scraping / social listening via the model's search tool. `src/lib/retailers.ts` (`isAllowedRetailer`) is the retailer allowlist.
- `src/lib/ai/*` — model clients and IDs. `models.ts` is safe for the client; `*.server.ts` is server-only. `gemini.server.ts` (`getGemini`, `hasGemini`, `aiErrorMessage`) is the pattern to mirror for any new provider.
- `src/routes/api/*` — server routes (agent, tts, stt, research, image, social).
- `src/components/agent/ProposalCard.tsx` — Approve / Edit / Reject; an action runs only on an explicit Approve click.
- `.agents/skills/gemini-api-dev/` — Gemini API skill (same copy in `.claude/skills/`).

## Rules
1. **Secrets are server-only.** Read `process.env.*` inside functions, never at module scope (Workers bind env per request). Never import a `*.server.ts` file from client code. Never log or return API keys; redact them in error messages.
2. **Human-in-the-loop is non-negotiable.** The agent may only *propose* actions through `propose_action`. Nothing is executed without the user's Approve.
3. **Citations are validated server-side.** Evidence ids returned by the model must exist in the evidence map; drop any that don't. Keep this behaviour for every provider.
4. **Keep limits:** ≤8 tool rounds (3 for the `lookup` route), ≤20 tool calls, ≤2 competitor scrapes, 150 s deadline (`MAX_ROUNDS`, `MAX_TOOL_CALLS`, `MAX_SCRAPES`, `DEADLINE_MS` in `agent.server.ts`).
5. **Bilingual:** user-facing strings exist in EN and 繁體中文 (`src/lib/i18n.tsx`). Add both when you add UI text.
6. **Demo mask is display-only.** Never apply it to data sent to the model.
7. Small, reviewable diffs. No dependency upgrades unless the task needs them. Update `README.md` and `docs/TECHNICAL.md` when behaviour changes.

## Model providers (target state — being added by the "Ace on OpenAI" task)
- `AI_PROVIDER=gemini` (default) uses `GEMINI_API_KEY`.
- `AI_PROVIDER=openai` uses `OPENAI_API_KEY` with the OpenAI Responses API.
- Model IDs live only in `src/lib/ai/models.ts`.
